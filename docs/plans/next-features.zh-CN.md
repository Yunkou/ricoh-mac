# 接下来的功能

本文整理已经决定或已经记录在需求与方案中的后续工作，并给出建议顺序。不引入此前没有提出或规划过的功能。

## 发布到远程仓库

在 M6 电脑上，使用 Yunkou 账号执行 `gh auth refresh -s workflow`，完成授权后将本地 `main` 上的两个提交推送到 `origin/main`。这两个提交是发版流程的编译缓存与并行拆分，以及照片详情页与拍摄信息面板。此步骤不打标签，也不发布版本。推送工作流文件需要 `workflow` 权限。

## 下一步实现

建议按下列顺序推进。前两项是下一次发版和已实现功能的质量所需；其后按第一版里程碑继续。

1. **产品化发布说明，从下一个版本开始使用。** 按 [release-notes.zh-CN.md](release-notes.zh-CN.md) 改发版工作流：读取 `docs/releases/` 中对应版本的中英文说明，再拼接安装步骤与校验段。安装步骤为：解压、拖入「应用程序」、按住 Control 点按并选择「打开」。校验码放在最后。缺少该版本说明文件时，发版作业应失败。已发布的 v0.2.0 GitHub Release 页面不重写；`docs/releases/v0.2.0.zh-CN.md` 与 `docs/releases/v0.2.0.en.md` 作为后续版本的模板保留。此项放在前面，是因为下一次打标签发版需要先具备新的页面格式。

2. **对照实拍的 GR IIIx 文件核对 Ricoh MakerNote。** 已于 2026 年 11 月 15 日（Asia/Shanghai）用可公开下载的机内直出 GR IIIx JPEG 与 DNG 完成核对。来源、证据和未覆盖项见 [gr-iiix-makernote-verification.zh-CN.md](gr-iiix-makernote-verification.zh-CN.md)。实拍 IIIx 文件使用紧凑的 Pentax 布局 MakerNote，而不是第一版解析所依据的 ExifTool Ricoh 0x10xx 表；该缺陷已经修复。已验证：型号、未裁切 40 mm、图像设定“标准”和“单色”、对焦手动 / 自动区域 / 选择对焦，以及 ND 关闭。下列各项未经实拍覆盖，不能宣称全覆盖：裁切 50 mm 与 71 mm、Snap、全按快门 Snap、ND 开启、开尔文色温，以及其他图像设定。在 GR IIIx 文件上，未裁切仍显示为 40 mm，裁切仍显示为 50 mm 或 71 mm，不得使用 GR III 的 35 mm 或 47 mm 标签。此项紧跟现有详情页，属于已实现功能的核对，而不是新功能。

3. **相册网格中的 DNG 预览。** 已实现。相册网格复用详情页同一套只读提取：有内嵌 JPEG 预览时，格子显示来自 `preview-cache` 的缩略图；没有或无法使用时，沿用「无法预览」占位。仍不得写回原片。这不是传感器级 RAW 解码。

4. **选片：1 到 5 星，以及已选、排除。** 已实现。这是需求中的第三里程碑。每张照片可以有 1 到 5 星或未评级，以及一种标记：已选、排除或无标记。已选与排除互斥；星级与标记相互独立。相册网格与照片详情页显示一致的标记，并都提供指针编辑入口。快捷键在「照片」和详情页中、已有聚焦或正在查看的照片、且不在编辑文本时生效：`0`–`5` 设定星级（`0` 清除星级；再按同一星级也会清除），`P` 切换已选，`X` 切换排除，`U` 只清除标记。相册可按标记或星级筛选。

   标记写入规范的 XMP sidecar，文件名为 `{file_name}.xmp`（含原片扩展名），例如 `R0001234.JPG.xmp` 与 `R0001234.DNG.xmp`。同名 JPEG/DNG 因此各有一份 sidecar，写入时不会覆盖另一张照片的评分。仅当文件夹中没有共享同一词干的其他照片时，才会读取 `{stem}.xmp`（如 `R0001234.xmp`）；写入始终使用规范路径，并保持 `{stem}.xmp` 不动。星级存为 `xmp:Rating`，取值为 0 到 5。读到 `-1`（Adobe 用来表示排除的取值）时视为未评级，且不会写出 `-1`，从而不把排除与星级绑在一起。标记存为 `ricohMac:Flag`（`picked` 或 `rejected`），命名空间为 `http://ns.yunkou.ricoh-mac/1.0/`；无标记时省略该属性。未知的 XMP 字段和命名空间予以保留。已有 sidecar 损坏时不改写该文件，并向用户报错。写入是原子的（先写隐藏的 `.name.{pid}.partial`，再重命名到位）。路径中的穿越成分会被拒绝，包含 `<!DOCTYPE>` 或 `<!ENTITY>` 的文档也会被拒绝。

   同一标记会镜像到可重建的 SQLite 索引 `data_dir()/cull-index.sqlite`，以规范的保存位置路径和文件名为键。sidecar 是权威来源。若 sidecar 缺失，可以显示此前索引中的记录。若 sidecar 写入失败，不会更新索引，界面也不会把这次修改显示为已保存。若 sidecar 写入成功而随后索引失败，仍返回错误，以便下次载入时重建索引。原 JPEG 与 DNG 字节不会被写入，标记也不会写回相机。
## 后续里程碑

- **传感器级 RAW / DNG 预览与直方图。** 真正依据传感器数据的画面和直方图，不属于当前拍摄信息面板的范围。解码库与许可另作决定，见下文。
- **若无线不能传输 DNG，第一版如何满足 RAW 预览需求。** 此项留在需求文档的真机验证清单中，须在真机测试后决定。
- **应用 LICENSE 文件。** 仓库目前为字体和图标提供了许可文本，应用本身的许可文件尚未加入。
- **对外应用名称与最终 bundle id。** 当前开发用标识符是 `com.yunkou.ricoh-mac`，不是最终身份。
- **图标强调色是否采用更高饱和度。** 仅在有明确需要时再调整。

## 仍需决定的事项

- 若以后做传感器级 DNG 预览或直方图，是接受 rawler 的 LGPL-2.1，还是在完成许可评估后采用 ImageIO 或其他解码库。当前不在二者中先行选定。
- 对外应用名称和最终 bundle id。
- 发布标题使用「Ricoh Mac」，还是继续使用当前的应用文件名。
- 发布说明末尾是否保留指向提交比较的链接。
- 图标强调色是否需要更高饱和度。
- 应用是否应附带 LICENSE 文件。

需求文档第 9 节中其余相机 HTTP 事项，仍须在真机上验证，不在本清单中展开为产品功能。
