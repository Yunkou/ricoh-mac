## 发现

### P1 · 「1:1」把显示栅格说成原片倍率

- **位置：** `ui/copy.ts`（`actualSize`: 「1:1」，`shortcutFit`: 「适应窗口或 1:1」）；`ui/components/photo-detail.tsx` 中 `previewStyle(true, naturalSize())` 使用 `Image` `onLoad` 尺寸再除以 `pixelRatio()`；`ui/components/photo-info.tsx` 的「尺寸」优先用 Exif / DNG 照片像素（`details.width/height`）。`DESIGN.md` 把该模式写成 “actual size (1:1)”。
- **影响：** 看 RAW 显影或 DNG 嵌入预览时，用户会以为正在以照片像素 100% 检视。RAW 显影长边上限是 4096，嵌入预览通常更小；信息面板仍可能显示 6000×4000，和「1:1」画面不一致。这与「不得把显示栅格冒充原片或嵌入预览升级」的产品规则冲突。
- **最小修正：** 将控件与快捷键改成「显示像素」或「显示尺寸」，并在 RAW / 嵌入预览时标明不是原片像素。不要把 JPEG 原图路径上的真实 1:1 和降采样栅格用同一个「1:1」。信息面板可同时列出照片尺寸与当前显示尺寸。
- **验证：** 源码已确认。需要在真实窗口用同一张 GR IIIx DNG 对照：面板尺寸、适应窗口、以及所谓「1:1」的像素，确认文案是否仍误导。
- **边界：** 未在真实窗口目视；未测量屏幕上的 CSS 像素是否等于 4096 或 6000。
- **修复状态：** 已修正文案与信息面板。JPEG 原片在显示像素模式下称为「原片 1:1」；RAW 显影或嵌入预览称为「显示尺寸」。面板在两者不同时分别列出「照片尺寸」与「显示尺寸（RAW 显影 / 嵌入预览）」。快捷键改为「适应窗口或显示像素」。无头测试已覆盖控件标签与 6000×4000 / 4096×2731 的区分。仍需在真实窗口用同一张 GR IIIx DNG 核对应和「显示尺寸」是否仍可能被看成原片 100%。

### P1 · 相册紧凑星标小于 24 CSS px，且无间隙

- **位置：** `ui/components/cull-controls.tsx`，`variant="compact"` 时星标为 18×18，`gap: 0`，字号 12。详情页星标为 28 px。
- **影响：** 低于 WCAG 2.5.8 的 24 CSS px 下限（除非适用例外）。相邻命中区重叠，网格里容易误点邻近星级。这是指针优先的 Mac 应用，不是以触控为主，但仍有选片准确性风险。
- **最小修正：** 紧凑星标至少 24×24，并保证相邻 24 px 圆不相交；或保留外观、扩大不可见命中区。不要把详情页 28 px 控件再缩小。
- **验证：** 源码已确认尺寸。需要在真实窗口用指针（及若适用的触控）点相邻星级，并检查焦点环是否互相重叠或难以分辨。
- **边界：** 未做指针或触控实测。WCAG 对纯指针桌面控件的适用程度，需在视觉验收时一并判断。
- **修复状态：** 已把紧凑星标命中区改为 24×24，相邻间隙 4 CSS px，详情页 28 px 未缩小。为容纳换行后的标记按钮，相册说明行高度从 54 调到 72，不扩大最小格子。无头测试锁定命中区与说明行预算。仍需在真实窗口用指针检查误点与焦点环。

### P2 · 筛选会留下当前照片，但没有标明它不符合筛选

- **位置：** `ui/state/cull.ts` 的 `filterAlbumPhotos(..., keepId)`；`ui/state/app-model.ts` 的 `setAlbumFilter` / `refreshVisiblePhotos`；`ui/state/cull.test.ts` 覆盖「保留当前照片」。相册头可能仍显示「共 n / 总数」。
- **影响：** 这能避免详情页或焦点在筛选后突然空白，不是功能阻断。但未匹配的照片仍留在可见列表与上一张 / 下一张顺序中，又没有标记，用户会以为它符合筛选，或觉得计数不对。
- **最小修正：** 给被保留但不匹配的格子或详情页加一句简短说明，或提供「仅看符合筛选的照片」从而退出保留。换片离开后应重新应用纯粹筛选，避免这份保留一直留在列表里。
- **验证：** 单元测试已确认保留行为。无头 UI 测试覆盖了筛选隐藏其他照片，以及取消标记后的空状态。需要在真实窗口看：详情中途改筛选、再按上一张 / 下一张，保留项是否可辨。
- **边界：** 未目视保留项的外观，也未跑「详情中改筛选再换片」的无头测试。
- **修复状态：** 已在格子和详情页标明「不符合当前筛选」。相册计数只统计符合筛选的照片。上一张 / 下一张只在符合筛选的照片之间移动，索引不再把保留项算进筛选顺序。离开该照片后，保留不再留在列表里。无头测试已覆盖标注、计数、换片和离开后的纯粹筛选。详情页本身仍没有筛选条，因此「详情中途改筛选」仍需在有真实窗口、且若日后把筛选入口放到详情时再目视。

- **影响：** 一次点击就会去掉已保存的网络配置和钥匙串密码。可以再保存，但要重新输入。不符合「破坏性操作先确认」的防错启发式。

- **验证：** 源码已确认无确认步骤。需要在真实设置面板看文案与误触风险。不要用用户的真实钥匙串做实验。
- **边界：** 未点击真实设置窗口。
- **修复状态：** 已增加确认步骤。第一次点击「删除」不会移除配置；确认文案写明将同时删除钥匙串中已保存的密码。取消后回到删除按钮。无头测试覆盖「先确认才删除」和「取消不删除」。仍需在真实设置面板看文案、误触风险和焦点顺序。不要用用户的真实钥匙串做实验。

### P2 · 标记保存失败有提示，成功几乎只有控件回写

- **位置：** `ui/state/app-model.ts` 的 `writeMarks`：成功后才 `applyLocalMarks`，失败则 `notice` 为「无法保存标记。」加上错误字符串。成功时若先前有失败提示则清掉。`ui/App.test.tsx` 覆盖「失败保存不显示为成功」。

- **最小修正：** 在控件上加短暂的进行中 / 已保存状态，失败时仍用现有 notice，不要在每次打星时弹持久成功条。
- **验证：** 无头测试已覆盖失败路径。需要在真实窗口看 notice 在相册和详情中是否足够显眼，以及慢保存时的控件状态。
- **边界：** 未测真实 sidecar 写入的时间或 notice 在 vibrancy 上的对比度。
- **修复状态：** 已在打星 / 标记过程中显示「正在保存…」，成功后显示「已保存」。失败仍只用现有 notice，不增加持久成功条。无头测试覆盖进行中、成功和失败路径。仍需在真实窗口看 notice 是否足够显眼，以及慢保存时的观感。
