## 1. 背景与目标

理光 GR IIIx 可以把照片记在机身或 SD 卡上。官方无线导入主要面向智能手机上的 Image Sync，而不是 Mac 上的桌面工作流。本项目要做一款 Mac 应用：在相机开启 Wi-Fi 后连接机身，浏览并导入照片，在本地相册里快速选片，并预览 RAW（DNG）。

第一版只服务这一条路径：从相机到本机，再在本机上选片。不把 AI 挑片放进第一版。

---

## 2. 目标用户与场景

**目标用户：** 使用理光 GR IIIx 的摄影师或爱好者，主要在 Mac 上整理照片，希望少插卡、少依赖手机应用。

典型场景：

- 外出回来后打开相机 Wi-Fi，在 Mac 上查看缩略图，把选定的 JPEG 或 DNG 导入本地相册。
- 在没有相机、也没有网络时，打开已经导入的相册，快速浏览、打星或标记，并打开 RAW 预览。
- 导入中断后再次连接，应用应能继续未完成的传输，且不重复写入已经完整导入的文件。

---

## 3. 范围内与范围外

### 3.1 第一版必须有

- Wi-Fi 连接相机。
- 浏览并导入相机里的照片。
- 本地相册浏览。
- 快速选片、打星或标记。
- RAW / DNG 预览。

### 3.2 第一版不含

- AI 辅助挑片（后续版本候选）。
- 多品牌相机支持。
- 自动删除、覆盖或改写相机上的文件，或已导入原片的像素数据。
- 修图、冲 RAW 出片、云同步、社交分享。
- 远程快门、实时取景、改相机参数（第一版不需要拍摄控制）。
- 用蓝牙唤醒相机。
- 对外分发安装包、Developer ID 签名，以及公证。第一版仅供个人使用。

### 3.3 安全边界

第一版对相机只使用只读探测与下载类请求。不调用会关机、关闭无线、触发快门或改参数的接口。这些接口不在第一版范围内；以后若要加入，需要变更范围并在真机上验证。

## 4. 功能需求

每项包含用户故事和验收标准。涉及相机无线能力的条款依据公开资料编写，并需在真机上验证。

### 4.1 Wi-Fi 连接相机

**用户故事：** 作为用户，我进入「设备」，看到已保存的相机配置；打开相机 Wi-Fi 后，可以从某个配置连接，加入已保存的相机网络、探测相机，并看到连接是成功、失败，还是仍需补充资料。

**已决定：** 第一版在首次连接时保存相机配置（型号、序列号、固件，以及相机 Wi-Fi 名称），并把 Wi-Fi 密码写入 macOS 钥匙串，不写入明文配置。之后点击「连接相机」会自动切换到该网络，等待 `192.168.0.1` 可达后再探测并载入照片。应用会记住切换前的网络，并在导入完成或用户主动断开后，默认自动切换回去，同时在界面上提供明确的切回操作。这取代了此前「第一版只支持手动加入相机 Wi-Fi」的决定。若自动切网失败，仍提供手动加入的说明作为回退。

**验收标准：**

- 应用提供清楚的连接步骤：在相机上打开无线局域网。若尚未保存配置，用户可输入相机屏幕上显示的 SSID 和密码（官方 Image Sync 连接说明要求在相机 LCD 上查看密码；不同机型操作以[使用说明书](https://www.ricoh-imaging.co.jp/english/support/man-pdf/gr-3x.pdf)为准）。若电脑已经手动加入相机网络，应用在权限允许时应自动读取当前 SSID，并只询问密码。
- 保存配置后，点击「连接相机」应切换到已保存的 SSID，等待相机在 `192.168.0.1` 上响应，再用只读请求探测可达性，并显示成功、失败或超时。不得把未验证的状态显示为已连接。
- 密码只保存在 macOS 钥匙串中。配置元数据保存在应用数据目录。「设备」列出已保存的相机配置，并可以从选定的配置发起连接。设置面板可以编辑或删除当前配置。
- 失败时给出可理解的原因（密码错误、相机无线局域网未打开、超时、定位权限被拒绝、无法加入网络），并且不修改相机状态。自动切网失败时，回退到手动加入说明。
- 导入完成后默认切换回原来的网络，界面上也提供「切换回原来的网络」。用户可以关闭自动切回。
- 若到相机的网络被代理占用，界面用简明提示说明相机可能连不上，并请用户把相机网络排除出代理后再试。
- 不要求先安装或配对官方 Image Sync。是否必须先做官方应用或蓝牙配对，需在真机上验证。

公开资料（非正式官方 SDK，需在真机上验证）：多份社区逆向与实现指出，GR IIIx 打开 Wi-Fi 后自身作为接入点，HTTP 服务在 `http://192.168.0.1/`（80 端口），只读探测常见为 `GET /v1/ping` 与 `GET /v1/props`。来源：[secretsauce 逆向笔记](https://notes.secretsauce.net/notes/2022/06/16_ricoh-gr-iiix-80211-reverse-engineering.html)、[Namako 的 GR3x 分析](https://namako.tw/2024/05/11/gr3x-wireless-api/)、[CursedHardware 社区 OpenAPI](https://github.com/CursedHardware/ricoh-wireless-protocol)、[snmkl/ricoh.app](https://github.com/snmkl/ricoh.app)。Ricoh 未公开同名官方 HTTP SDK。

### 4.2 浏览并导入相机里的照片

**用户故事：** 作为用户，我连接成功后能浏览相机里的照片缩略图，选择要导入的文件，把它们完整保存到我指定的本地目标文件夹，并且可以中断后续传。

**已决定：** 所有导入文件放入同一个目标文件夹，并保留相机上的原始文件名。沿用「先写临时文件、校验完整后再改名」以及现有的去重策略。

**验收标准：**

- 能列出相机上可见的照片或文件夹，并以缩略图浏览。列表为空、加载失败或被截断时，界面说明原因，不假装「相机里没有问题」。
- 用户可以多选，并导入到事先选定的单个目标文件夹。导入过程显示进度、成功、失败和跳过（例如已存在的完整文件）。
- 目标路径使用相机原始文件名，不再按日期或相机文件夹名再建一层目录。
- 导入写入同一目录下的临时文件，校验完整后再原子替换到最终路径。中断后再次导入同一文件时，应从断点或重新校验后续传，且不覆盖已经完整且内容相同的文件。
- 若两个来源文件在目标文件夹中会落到同一文件名，但内容不同，应用必须报告冲突，不得覆盖已有的完整原片。
- 导入不修改、不删除、不移动相机上的原片。
- 导入结束后，界面提供「查看照片」，用于打开「照片」。
- 若相机在无线路径上能提供 DNG，第一版应允许导入 DNG。若真机证明无线只能得到 JPEG，应用必须明确说明，而不能把 JPEG 说成 RAW。若无线无法传输 DNG，第一版的 RAW 预览应如何覆盖，仍待真机测试后再决定。

公开资料（需在真机上验证）：社区实现常用 `GET /v1/photos` 列出文件夹与文件，`GET /v1/photos/{folder}/{file}` 下载原图，`?size=thumb` 取缩略图，`GET /v1/photos/{folder}/{file}/info` 取元数据。预览尺寸参数存在分歧：Namako 记录 `size=xs`（约 1920×1080），snmkl/ricoh.app 记录 `size=view`，社区 OpenAPI 则同时列出 `xs`、`view`、`thumb`，且像素值与上述不完全相同。这些查询参数与响应 JSON 的实际形状必须在真机上核对。社区 OpenAPI 的下载响应含 `image/jpeg` 与 `image/x-adobe-dng`，提示原文件下载可能包含 DNG；但官方 Image Sync 功能说明写明「调整尺寸后再传输只支持 JPEG」。因此「无线能否传输完整 DNG」不能根据现有官方文案直接下结论。

### 4.3 本地相册浏览

**用户故事：** 作为用户，我无需连接相机即可打开「照片」，浏览已导入保存位置的照片缩略图，打开大图，并切换到上一张或下一张。

**验收标准：**

- 「照片」可从启动页、区域内的分段切换，以及导入结束后的「查看照片」进入，不依赖相机连接或网络。
- 用户通过系统文件夹对话框选择相册根目录（也就是导入所用的那个目标文件夹）。应用列出该文件夹下的照片文件，不进入子文件夹，也不扫描系统「照片」图库或其他未授权路径。
- 界面提供虚拟化缩略图网格和照片详情页。在网格中点击照片，或按空格、回车，打开详情页。打开照片后，用户可以通过「返回」或 Esc 回到网格，并在同一文件夹中切换到上一张或下一张。详情页以侧栏展示拍摄信息。
- JPEG 可在网格和详情页中显示。若 DNG 含有内嵌 JPEG 预览，相册网格和详情页都可以显示该预览。详情页会标明这是预览，而不是原片像素。无法显示的文件给出说明，而不是空白块。这不是传感器级 RAW 解码。
- 浏览为只读：不得在保存位置中创建、改写、移动或删除原片。
- 刷新或再次进入「照片」时，应看到约定扫描范围内后来增加的文件。

### 4.4 快速选片、打星或标记

**用户故事：** 作为用户，我在浏览时可快速给照片打星或加上标记，之后能按星级或标记筛选，并且这些选择在下次打开应用时还在。

**已决定：** 星级为 1 到 5 星。标记有两种：已选、排除。评分与标记同时写入 XMP sidecar，并保存在本地 SQLite 索引中。

**验收标准：**

- 每张照片可设 1 到 5 星，或保持未评分。
- 支持两种标记：已选、排除。一张照片可以没有标记，也可以带其中一种标记。已选与排除互斥。
- 键盘或指针都能完成打星和标记，不打断浏览节奏。在「照片」和详情页中，已有聚焦或正在查看的照片、且不在编辑文本时：`0`–`5` 设定星级（`0` 清除星级；再按同一星级也会清除），`P` 切换已选，`X` 切换排除，`U` 只清除标记。
- 可以按星级或标记筛选列表。
- 评分与标记持久保存：写入该照片旁的 XMP sidecar，并镜像到本地 SQLite 索引，供筛选使用。第一版不得把这些信息写入相机，也不得改写已导入原片的像素字节。存储细节见技术文档。
- 取消标记或改星级后，筛选结果随即更新，sidecar 与索引保持一致。

### 4.5 RAW / DNG 预览

**用户故事：** 作为用户，我在本地相册（以及在无线浏览可行时的相机列表）里能预览 DNG，而不必先用其他软件冲图。

**验收标准：**

- 对本地 DNG，相册网格和详情页在存在内嵌 JPEG 预览时可以显示该预览，而不是完整 demosaic 冲图。详情页会标明这是预览。这不是传感器级 RAW 解码。理由见技术文档。
- 若某张 DNG 没有可用预览，界面说明「无法预览」，并仍列出文件名等基本信息。
- 预览失败不得损坏或改写该 DNG。
- 相机列表中的 DNG 缩略图，取决于无线接口实际返回的数据，需在真机上验证。
- 若真机测试表明无线不能传输 DNG，第一版是否仍以「已经在本地的 DNG」（例如从存储卡拷入目标文件夹）满足 RAW 预览需求，将在测试后决定。在此之前，该项列在「待真机验证」中。

官方说明书确认机身可以记录 DNG，并可同时记录 RAW 与 JPEG。见 [GR III / GR IIIx FAQ](https://www.ricoh-imaging.co.jp/english/support/qa/gr-3/index.html) 与[使用说明书](https://www.ricoh-imaging.co.jp/english/support/man-pdf/gr-3x.pdf)。

## 5. 非功能需求

### 5.1 性能

- 缩略图网格应能滚动浏览常见一次拍摄量（目标：至少数百张的本地列表仍可操作）。精确上限将在实现时依据测量确定，并在技术上避免一次无界解码全部原图。
- 社区记录指出相机 Wi-Fi 为 2.4 GHz，缩略图可能较慢，需要懒加载和本机缓存。见 [snmkl/ricoh.app](https://github.com/snmkl/ricoh.app)。具体速率需在真机上测量。

### 5.2 离线

- 本地浏览、预览、打星和标记在无相机、无互联网时必须可用。
- 仅连接探测、相机浏览和导入需要相机网络。应用在离线时不得假装相机已连接。

### 5.3 隐私

- 照片与评分默认只留在用户本机。第一版不把原片或预览上传到任何服务。
- 应用配置保存在系统为该应用提供的数据目录中，不写入用户相册目录以外的无关位置。
- 第一版不做使用分析或崩溃数据外发。

### 5.4 原片只读安全

- 不修改、不删除、不移动相机上的文件。
- 不改写已导入原片（JPEG、DNG 或其他原文件）的像素字节。评分与标记写到 XMP sidecar 和应用自己的 SQLite 索引中。
- 不以「整理」为名自动重命名或覆盖用户已有的完整文件。
- 测试不得使用用户的真实相册或真实配置作为夹具。

### 5.5 深色外观

界面使用固定深色。这是已锁定的第一版外观决定，不跟随系统的浅色外观。

### 5.6 签名与分发

**已决定：** 第一版仅供个人使用。使用 `nsh package` 提供的 ad hoc 签名即可，不做 Developer ID 签名，也不做公证。对外分发安装包不在第一版范围内。

## 6. UX 原则

第一版界面遵循 [Impeccable](https://impeccable.style/) 的 Operate 模式，并锁定以下决定：

- 全应用固定深色，强调色使用暖琥珀，只用于主操作、选择和焦点。
- 界面文案使用简洁中文。
- 不放产品名大标题，也不使用常驻侧栏。
- 启动后先显示两个功能入口：「设备」和「照片」。进入某一区域后，可用紧凑的分段控件在二者之间切换，并用返回控件回到启动页。
- 圆形图标按钮只作为角落里的设置入口，用于更改保存位置、相机网络配置和相机地址，不承担主导航。
- 在「设备」中，相机里的照片以虚拟化缩略图网格展示。主操作是「导入已选」，「全部导入」是次要操作。在「照片」中，点击缩略图打开照片详情页，而不是进入导入多选。
- 尚未尝试连接时，不把「未连接」显示为错误。探测成功后自动载入照片列表。导入进度、跳过、冲突和失败要加以区分。

视觉 token 与组件规则见 [DESIGN.zh-CN.md](../DESIGN.zh-CN.md)。

## 7. 里程碑

以下为实现顺序，不是已排期的时间表。

1. **M0 文档：** 产品需求与技术设计。
2. **M1 资料库、连接、列表与导入：** 选择并记住保存位置；保存相机网络配置并在之后自动切换 Wi-Fi、探测连接；列出照片；将选定或全部文件导入该文件夹。范围与验收标准见第 11 节。界面遵循第 6 节的 UX 决定。
3. **M2 本地相册浏览：** 浏览保存位置中已有文件的缩略图和照片详情页，包括在没有相机时使用。本里程碑包含拍摄信息面板，以及详情页中的 DNG 内嵌预览。相册网格中的 DNG 缩略图见 M4。
4. **M3 选片：** 1 到 5 星、已选与排除标记、筛选，以及 XMP sidecar 与 SQLite 的持久化。
5. **M4 RAW 预览：** 相册网格中的 DNG 缩略图，复用详情页同一套只读内嵌 JPEG 提取，以及后续的传感器级 RAW 预览与直方图。网格缩略图这项工作已进入产品。相机列表中的 DNG，以及无线无法传输 DNG 时第一版如何满足预览需求，以真机测试结果为准。

AI 辅助挑片、蓝牙唤醒等放入更后的版本候选。

## 8. 开放问题

1. 打星与标记的具体快捷键是什么？已决定，并写入第 4.4 节：在「照片」和详情页中，已有聚焦或正在查看的照片、且不在编辑文本时，`0`–`5` 设定星级（`0` 清除星级；再按同一星级也会清除），`P` 切换已选，`X` 切换排除，`U` 只清除标记。这些快捷键不取代第一里程碑已确定的导入与选择快捷键：Command-A 全选，Escape 清除选择或关闭设置，Command-Return 导入已选，Command-R 刷新列表。
2. 应用的对外名称，以及个人使用时采用的 bundle id，分别是什么？当前开发用标识符是 `com.yunkou.ricoh-mac`，不是最终身份。

## 9. 待真机验证

- GR IIIx 在当前固件下，Wi-Fi 接入点地址是否总是 `192.168.0.1:80`，以及 `GET /v1/ping`、`GET /v1/props` 的真实响应。
- `GET /v1/photos` 的 JSON 形状、分页或截断行为，以及固件差异。
- `size=thumb`、`size=xs`、`size=view` 在 GR IIIx 上是否存在，以及各自尺寸与格式。
- 不带 `size` 的 `GET /v1/photos/{folder}/{file}` 能否下载完整 DNG，以及 DNG 是否出现在列表中。
- 若无线不能传输 DNG，第一版是否仍以已经在本地的 DNG（例如从存储卡拷入目标文件夹）满足 RAW 预览需求。此项将在真机测试后决定。
- HTTP 是否完全无需鉴权，以及是否必须先用官方 Image Sync 或蓝牙配对。
- 相机端 `PUT /v1/photos/{folder}/{file}/transfer` 是否会改机身状态；第一版默认不调用。
- 无线导入的实际速度、稳定性，以及大 DNG 在弱信号下的表现。

## 11. 第一里程碑

第一里程碑覆盖从本地保存位置出发，只读探测相机、列出照片，并导入到该文件夹的第一条工作路径。相机 HTTP 行为依据社区公开资料编写，需在真机上验证。

### 11.1 范围

1. 首次启动时，用户选择本地保存位置。路径保存在应用数据目录中，之后可以更改。
2. 首次连接时，应用保存相机配置（型号、序列号、固件，以及相机 Wi-Fi 名称），并将密码写入 macOS 钥匙串。之后点击「连接相机」会自动切换到已保存的 SSID，等待 `192.168.0.1` 可达，再用只读请求（`GET /v1/ping` 与 `GET /v1/props`）探测相机，显示已连接或未连接，并在可获得时显示型号信息。自动切网失败时，仍提供手动加入说明作为回退。若电脑在相机网络上仍需要互联网，建议使用网线或 iPhone 网络共享。导入完成后默认切换回原来的网络，界面上也提供明确的切回操作。若到相机地址的路由经过 `utun` 隧道，界面给出提示。相机 HTTP 源地址可在开发时配置，默认是 `http://192.168.0.1`。
3. 应用通过 `GET /v1/photos` 列出相机上的照片；在 `size=thumb` 可用时请求缩略图。
4. 用户可将选定照片或全部已列出照片下载到同一个保存位置。保留原始文件名。每个文件先写入同一目录下的临时文件，在已知期望大小时进行校验，再改名为最终文件。名称与大小都相同的已有文件会被跳过。显示进度和逐文件错误。应用不删除、不重命名、不改写相机上的文件，也不覆盖大小不同的完整本地文件（这种情况报告为冲突）。

评分、标记、RAW 冲图和分发不在第一里程碑范围内。

### 11.2 验收标准

- 尚未选择保存位置时，界面在导入前要求用户选择。选定后显示路径，并允许更改。
- 只有只读 ping 成功时，才把状态显示为已连接。失败和超时显示为未连接，而不是已连接。当 `GET /v1/props` 提供型号与固件时予以显示。
- 界面包含首次保存相机网络、之后自动切网、导入后切回原来网络，以及手动加入作为回退的说明，还有以太网或 USB 网络共享的建议。密码不出现在配置文件中。若到相机地址的路由经过隧道接口，界面给出提示。
- 成功执行 `GET /v1/photos` 后显示照片列表。列表为空、失败或无法解析时说明原因，不把它显示成相机状态正常且没有照片。
- 导入时保留原始文件名，使用 `.partial` 临时文件，跳过名称与大小都相同的文件，报告同名但大小不同的冲突且不覆盖，并在单个文件失败后继续处理其余文件。
- 尚未尝试连接时，不把探测前的状态显示为连接错误。探测成功后自动载入照片，并以虚拟化缩略图网格显示。
- 「导入已选」是主操作，「全部导入」是次要操作。导入进行中禁用会重复触发导入的操作。进度条显示当前文件名；完成后的摘要区分已导入、已跳过、冲突和失败。
- 无界面测试在本地模拟 HTTP 夹具上覆盖 ping、列表、下载、去重、不完整下载恢复，以及相机不可达的情况。界面测试在隔离的模块替身上覆盖首启流程、选择、禁用导入和进度摘要。这些测试不能代替真机验证。

## 12. 第二里程碑

第二里程碑覆盖本地相册浏览、双入口信息结构、照片详情页、拍摄信息面板，以及详情页中的 DNG 内嵌预览。打星、标记、筛选，以及传感器级 RAW 预览不属于本里程碑。相册网格中的 DNG 缩略图是后来作为第四里程碑的第一项加入的，复用同一套只读提取。

### 12.1 范围

1. 启动后先显示两个功能入口：「设备」和「照片」。用户可用紧凑的分段控件在两个区域之间切换，并用返回控件回到启动页。
2. 「设备」列出已保存的相机配置，沿用第一里程碑的自动切网与钥匙串密码流程，并在此连接相机、浏览、选择和导入照片。
3. 导入结束后，界面提供「查看照片」，用于打开「照片」。
4. 「照片」列出已保存在单一保存位置中的照片，提供缩略图网格和照片详情页，并且在没有相机连接时仍可使用。列表为只读，且不进入子文件夹。

### 12.2 验收标准

- 启动后显示「设备」和「照片」，并且不把尚未尝试的连接显示为错误。
- 「设备」可以列出已保存的配置，从选定配置发起连接，然后按第一里程碑的方式浏览和导入。
- 「照片」无需连接相机即可打开。若尚未选择保存位置，该区域会要求用户选择。
- 相册网格列出保存位置下的照片文件，包括 JPEG 和 DNG 的文件名。隐藏文件、`.partial` 文件和非照片文件不列入。
- 打开照片后进入详情页。用户可以通过「返回」或 Esc 回到相册网格，并切换到上一张或下一张。详情页展示拍摄信息。JPEG 可在网格和详情页中显示。若 DNG 含有内嵌 JPEG 预览，相册网格和详情页都可以显示该预览，详情页会标明这是预览。无法显示的文件给出说明，而不是空白块。
- 浏览不修改保存位置中的原片。
- 导入结束后，「查看照片」打开「照片」，并显示已导入的文件。
